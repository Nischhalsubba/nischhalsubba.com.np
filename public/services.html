How I work

Clearer decisions before prettier screens.

I clarify user journeys, hierarchy, language, states and responsive behavior first. Then I push the interface until it feels polished enough for the portfolio and practical enough for engineering.

01

Audit the current experience

Find where users lose context, confidence, or momentum across flows, content and interface states.

02

Structure the product story

Turn broad product ideas into clearer journeys, sections, screens and decisions that teams can align around.

03

Design the interface system

Create polished UI using reusable cards, buttons, grids, typography, spacing and interaction patterns.

04

Prepare handoff

Document states, responsive rules, edge cases, priorities and QA notes so engineering gets useful context.
